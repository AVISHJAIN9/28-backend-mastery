# Theory - CDN & CloudFront\n\n## CDN Overview\n\n### What is a CDN?\n- Content Delivery Network\n- Distributed servers worldwide\n- Caches content at edge locations\n- Reduces latency for users\n- Improves bandwidth efficiency\n\n## CloudFront Fundamentals\n\n### How CloudFront Works\n1. User requests content\n2. Routed to nearest edge location\n3. If cached, served immediately\n4. If not cached, fetched from origin\n5. Content cached for TTL\n6. Response returned to user\n\n### Key Benefits\n- **Speed**: Content served from nearby edge\n- **Reliability**: Failover to alternate origins\n- **Security**: Built-in DDoS protection\n- **Cost**: Reduced origin server load\n- **Scale**: Handles traffic spikes\n\n## Distribution Features\n\n### Cache Behavior\n- **TTL (Time To Live)**: How long content cached\n- **Default**: 24 hours for most content\n- **Short**: 1 hour for dynamic content\n- **Long**: 365 days for static assets\n\n### Invalidation\n- Force refresh of cached content\n- Immediate or batch operations\n- Useful for updates\n- Can include wildcards\n\n## Real-World Example\n\n### E-commerce Site\n```\nUser in Tokyo requests image:\n1. Request to CloudFront\n2. Routed to Tokyo edge\n3. Cache miss\n4. Fetch from US origin S3\n5. Cache at Tokyo edge\n6. Return to user (200ms)\n\nNext user in Tokyo:\n1. Request served from cache (5ms)\n```\n\n## Performance Metrics\n\n### Latency Reduction\n- Without CDN: 500-2000ms (globe)\n- With CDN: 50-200ms (local edge)\n- Improvement: 80-90%\n\n### Bandwidth Savings\n- Origin: 100 Mbps traffic\n- With CDN edge caching: 10-20 Mbps\n- Savings: 80-90%\n\n## Security Features\n\n1. **DDoS Protection**: Automatic mitigation\n2. **AWS Shield**: Free basic protection\n3. **Field-level encryption**: Sensitive data\n4. **Signed URLs**: Limited access tokens\n\n## Summary\n\n✅ CDN improves global performance\n✅ Edge caching reduces origin load\n✅ Invalidation for instant updates\n✅ Built-in security features\n✅ Highly scalable and reliable
