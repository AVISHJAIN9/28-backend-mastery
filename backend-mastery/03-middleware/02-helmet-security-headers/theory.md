# Theory & Concepts\n## Helmet Security Headers Overview\nHelmet.js sets HTTP security headers that protect against common web vulnerabilities like XSS (Cross-Site Scripting), clickjacking, and MIME type sniffing.\n\n## Key Security Headers\n- **X-Content-Type-Options: nosniff** - Prevents browser from interpreting files as wrong type\n- **X-Frame-Options: DENY** - Prevents embedding in iframes (clickjacking protection)\n- **X-XSS-Protection: 1; mode=block** - Legacy XSS protection for older browsers\n- **Content-Security-Policy** - Controls which resources can be loaded\n- **Strict-Transport-Security** - Forces HTTPS for all future requests\n- **Referrer-Policy** - Controls if referrer is sent to other sites\n\n## How Defense Works\nBrowser receives headers with response → Browser enforces policy → Attacks blocked\n\n## Default vs Custom\nHelmet provides sensible defaults but can be customized for specific needs. Most applications can use the default configuration without modification.
