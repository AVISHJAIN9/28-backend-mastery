# Module 13.4: Utility Types - Partial, Pick, Omit, Record, Readonly\n\n## What is this?\nTypeScript's built-in utility types that transform object types without modification. Use them to create flexible, reusable patterns for type constraints and transformations.\n\n## Why does it matter?\n- **DRY principle**: Define shapes once, transform them many ways\n- **API safety**: Explicitly expose/hide fields from different contexts  \n- **Code reuse**: Avoid creating similar types manually\n- **Maintainability**: Changes propagate automatically\n- **Type safety**: Compile-time validation of transformations\n\n## How it works (step by step)\n\n### 1. Partial<T> - Make all properties optional\n```typescript\ntype User = { id: number; name: string; email: string; password: string; }\ntype PartialUser = Partial<User>;  // All fields optional for updates\n\n// API endpoint for PATCH/PUT\napp.put('/users/:id', (req: Request<any, any, PartialUser>) => {...})\n```\n\n### 2. Pick<T, K> - Select specific properties\n```typescript\ntype PublicUser = Pick<User, 'id' | 'name' | 'email'>;\n// Result: { id: number; name: string; email: string; }\n\n// Safe to return in public API\nres.json(publicUser);  // password hidden\n```\n\n### 3. Omit<T, K> - Exclude specific properties\n```typescript\ntype SafeUser = Omit<User, 'password'>;  // Everything except password\n// Result: { id: number; name: string; email: string; }\n```\n\n### 4. Record<K, V> - Create mappings\n```typescript\ntype Role = 'admin' | 'user' | 'guest';\ntype Permissions = Record<Role, string[]>;\n\nconst permissions: Permissions = {\n  admin: ['read', 'write', 'delete'],\n  user: ['read', 'write'],\n  guest: ['read']\n};\n```\n\n### 5. Readonly<T> - Make immutable\n```typescript\ntype FrozenUser = Readonly<User>;\nconst user: FrozenUser = { /* ... */ };\nuser.name = 'fail'; // TypeScript error!\n```\n\n## Key concepts\n\n### Pattern: DTO Transformation\n```typescript\n// Full database model\ninterface User { id: number; name: string; email: string; password: string; createdAt: Date; role: string; }\n\n// API response DTO (Omit sensitive)\ntype UserResponse = Omit<User, 'password' | 'createdAt'>;\n\n// Update input (Partial)\ntype UpdateUserInput = Partial<Omit<User, 'id' | 'createdAt'>>;\n\n// Public profile (Pick)\ntype UserProfile = Pick<User, 'id' | 'name' | 'role'>;\n```\n\n### Pattern: Feature Flags\n```typescript\ntype Features = Record<'darkMode' | 'betaAPI' | 'notifications' | 'socialShare', boolean>;\n\nconst features: Features = {\n  darkMode: true,\n  betaAPI: false,\n  notifications: true,\n  socialShare: false\n};\n\n// Type-safe access\nif (features.darkMode) { /* enable */ }\n```\n\n### Pattern: Permission Matrix\n```typescript\ntype Permission = 'read' | 'write' | 'delete' | 'admin';\ntype Role = 'admin' | 'moderator' | 'user' | 'guest';\ntype RolePermissions = Record<Role, readonly Permission[]>;\n\nconst permissions: RolePermissions = {\n  admin: ['read', 'write', 'delete', 'admin'],\n  moderator: ['read', 'write', 'delete'],\n  user: ['read', 'write'],\n  guest: ['read']\n};\n```\n\n## Common mistakes\n\n❌ **Over-nesting utility types** - becomes unreadable\n```typescript\ntype Bad = Omit<Pick<Partial<User>, 'name' | 'email'>, 'email'; // Too much!\n```\n\n✅ **Create intermediate types**\n```typescript\ntype UpdateFields = Pick<User, 'name' | 'email'>;\ntype PartialUpdate = Partial<UpdateFields>;\n```\n\n❌ **Using Pick/Omit instead of interfaces** for unrelated shapes\n```typescript\ntype Blog = Pick<User, 'name' | 'email'>;  // Confusing - suggest new interface\n```\n\n✅ **Use when transforming related types**\n```typescript\ntype UserDTO = Omit<User, 'password'>;  // Clear relationship\n```\n\n❌ **Forgetting Readonly for shared constants**\n```typescript\nconst defaultConfig = { /* ... */ };  // Can be mutated!\n```\n\n✅ **Use Readonly for\n APIs**\n```typescript\nconst defaultConfig: Readonly<Config> = { /* ... */ };\ndefaultConfig.key = 'mutant';  // Error!\n```\n\n## Real world usage\n\n### Express API with DTOs\n```javascript\n// server.js\napp.post('/users', (req, res) => {\n  const input: CreateUserInput = req.body;\n  const user = userService.create(input);\n  const response: UserResponse = user;  // Type narrows automatically\n  res.json(response);\n});\n```\n\n### Role-based Access Control\n```javascript\nconst checkPermission = (role: Role, action: Permission) => {\n  return permissions[role].includes(action);\n};\n\nconst canDelete = checkPermission('admin', 'delete');  // true\nconst canDelete = checkPermission('user', 'delete');   // false\n```\n\n### Update Operations\n```javascript\napp.put('/users/:id', (req, res) => {\n  const updates: Partial<UserUpdateFields> = req.body;\n  const user = userService.update(req.params.id, updates);\n  res.json(user);\n});\n```\n\n## API Endpoints\n\n| Method | Path | Pattern | Notes |\n|--------|------|---------|-------|\n| PUT | `/users/:id/partial` | Partial<User> | Update any subset |\n| GET | `/users/:id/public` | Pick<User> | Return safe fields |\n| GET | `/users/:id` | Omit<User> | Hide password |\n| POST | `/validate-permission` | Record access | Permission lookup |\n| GET | `/features` | Record<string, bool> | Feature flags |\n| GET | `/permissions/:role/readonly` | Readonly<T> | Immutable perms |\n\n## Exercises\n\n1. **Transform Exercise**: Create `UserDTO = Pick<User, 'id' | 'name' | 'email'>` and use in API\n2. **Partial Update**: Implement PATCH endpoint accepting `Partial<UserUpdate>`\n3. **Feature Flags**: Define `FeatureFlags = Record<'feature1' | 'feature2', boolean>`\n4. **Permission Matrix**: Create role-based permission system using Record\n5. **Composition**: Define `type UpdateInput = Partial<Omit<User, 'id' | 'createdAt'>>`\n\n## Key Takeaways\n\n✅ **Partial<T>** - Make fields optional (updates)\n✅ **Pick<T,K>** - Select specific properties (DTOs) \n✅ **Omit<T,K>** - Exclude specific properties (hide sensitive)\n✅ **Record<K,V>** - Create mappings (permissions, flags)\n✅ **Readonly<T>** - Prevent mutations (constants)\n✅ Chain them for complex scenarios  \n✅ Create intermediate types for clarity"
