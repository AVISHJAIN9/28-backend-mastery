.env\n```\n\n**Configuration:**\n```\nNODE_ENV=development\nHTTP_PORT=4008\nLOG_LEVEL=info\nCORS_ORIGIN=http://localhost:3000\n```\n\n### Step 3: Start Server\n```bash\nnode server.js\n```\n\n---\n\n## Test Scenario 1: Create Schema Version\n\n### Objective\nCreate a new schema version for a collection.\n\n### Request\n```bash\ncurl -X POST http://localhost:4008/api/secure/schema/create \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"version\": \"1.0.0\",\n    \"collection_name\": \"users\",\n    \"schema\": {\n      \"id\": \"integer\",\n      \"name\": \"string\",\n      \"email\": \"string\"\n    },\n    \"migration_type\": \"add_field\",\n    \"changes\": {\n      \"added\": [\"id\", \"name\", \"email\"]\n    },\n    \"description\": \"Initial user schema\",\n    \"zero_downtime\": true\n  }' | jq .\n```\n\n### Expected Response\n```json\n{\n  \"success\": true,\n  \"message\": \"Schema version 1.0.0 created\",\n  \"schema\": {\n    \"version\": \"1.0.0\",\n    \"collection_name\": \"users\",\n    \"migration_type\": \"add_field\",\n    \"created_at\": \"2024-01-15T10:00:00Z\",\n    \"rollback_supported\": true\n  }\n}\n```\n\n### Verification\n```bash\ncurl http://localhost:4008/api/secure/schema?collection_name=users | jq .\n```\n\n---\n\n## Test Scenario 2: Add Optional Field (Non-Breaking)\n\n### Objective\nAdd optional phone field to users - zero-downtime change.\n\n### Step 1: Create New Schema\n```bash\ncurl -X POST http://localhost:4008/api/secure/schema/create \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"version\": \"1.1.0\",\n    \"collection_name\": \"users\",\n    \"schema\": {\n      \"id\": \"integer\",\n      \"name\": \"string\",\n      \"email\": \"string\",\n      \"phone\": \"string (optional)\"\n    },\n    \"migration_type\": \"add_field\",\n    \"changes\": {\n      \"added\": [\"phone\"]\n    },\n    \"description\": \"Add phone field\",\n    \"zero_downtime\": true\n  }' | jq .\n```\n\n### Step 2: Check Compatibility\n```bash\ncurl \"http://localhost:4008/api/secure/schema/check-compatibility?from_version=1.0.0&to_version=1.1.0&collection_name=users\" | jq .\n```\n\n### Expected Response\n```json\n{\n  \"success\": true,\n  \"compatible\": true,\n  \"from_version\": \"1.0.0\",\n  \"to_version\": \"1.1.0\",\n  \"message\": \"Schemas are compatible\"\n}\n```\n\n### Step 3: Align Data (Dry-Run)\n```bash\ncurl -X POST http://localhost:4008/api/secure/schema/align-data \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"from_version\": \"1.0.0\",\n    \"to_version\": \"1.1.0\",\n    \"collection_name\": \"users\",\n    \"batch_size\": 1000,\n    \"dry_run\": true\n  }' | jq .\n```\n\n### Expected Response (Simulated)\n```json\n{\n  \"success\": true,\n  \"message\": \"Data would be aligned to schema 1.1.0\",\n  \"alignment\": {\n    \"from_version\": \"1.0.0\",\n    \"to_version\": \"1.1.0\",\n    \"total_records\": 5432,\n    \"processed_batches\": 6,\n    \"status\": \"simulated\"\n  }\n}\n```\n\n### Step 4: Apply Alignment\n```bash\ncurl -X POST http://localhost:4008/api/secure/schema/align-data \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"from_version\": \"1.0.0\",\n    \"to_version\": \"1.1.0\",\n    \"collection_name\": \"users\",\n    \"batch_size\": 1000,\n    \"dry_run\": false\n  }' | jq .\n```\n\n---\n\n## Test Scenario 3: Breaking Change Migration\n\n### Objective\nMigrate from flat to nested schema (breaking change).\n\n### Step 1: Create Breaking Schema\n```bash\ncurl -X POST http://localhost:4008/api/secure/schema/create \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"version\": \"2.0.0\",\n    \"collection_name\": \"users\",\n    \"schema\": {\n      \"id\": \"integer\",\n      \"name\": {\n        \"first\": \"string\",\n        \"last\": \"string\"\n      },\n      \"contact\": {\n        \"email\": \"string\",\n        \"phone\": \"string\"\n      }\n    },\n    \"migration_type\": \"breaking\",\n    \"changes\": {\n      \"removed\": [\"email\", \"phone\"],\n      \"restructured\": true\n    },\n    \"description\": \"Restructure user schema\",\n    \"zero_downtime\": false\n  }' | jq .\n```\n\n### Step 2: Check Compatibility (Will Show Breaking Changes)\n```bash\ncurl \"http://localhost:4008/api/secure/schema/check-compatibility?from_version=1.1.0&to_version=2.0.0&collection_name=users\" | jq .\n```\n\n### Expected Response\n```json\n{\n  \"success\": true,\n  \"compatible\": false,\n  \"from_version\": \"1.1.0\",\n  \"to_version\": \"2.0.0\",\n  \"message\": \"Breaking changes detected: data alignment required\"\n}\n```\n\n### Step 3: Align Data with Warnings\n```bash\ncurl -X POST http://localhost:4008/api/secure/schema/align-data \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"from_version\": \"1.1.0\",\n    \"to_version\": \"2.0.0\",\n    \"collection_name\": \"users\",\n    \"batch_size\": 500,\n    \"dry_run\": true\n  }' | jq .\n```\n\n**Note:** With breaking changes, data transformation is complex and should be tested extensively.\n\n---\n\n## Test Scenario 4: Rollback Schema\n\n### Objective\nRollback to a previous schema version.\n\n### Step 1: Verify Current Version\n```bash\ncurl \"http://localhost:4008/api/secure/schema?collection_name=users\" | jq .\n```\n\n### Step 2: Rollback to v1.1.0\n```bash\ncurl -X POST http://localhost:4008/api/secure/schema/rollback \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"collection_name\": \"users\",\n    \"to_version\": \"1.1.0\",\n    \"verify_before_rollback\": true\n  }' | jq .\n```\n\n### Expected Response\n```json\n{\n  \"success\": true,\n  \"message\": \"Rolled back to schema version 1.1.0\",\n  \"current_version\": \"1.1.0\",\n  \"collection_name\": \"users\"\n}\n```\n\n### Step 3: Verify Rollback\n```bash\ncurl \"http://localhost:4008/api/secure/schema?collection_name=users\" | jq .\n```\n\n---\n\n## Test Scenario 5: Migration History\n\n### Objective\nView complete schema migration
