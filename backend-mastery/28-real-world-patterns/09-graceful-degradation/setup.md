Navigate to **Health Check** tab\n2. Select `userService` from dropdown\n3. Click **Get Service Health**\n\n**Expected Response:**\n```json\n{\n  \"service_name\": \"userService\",\n  \"status\": \"healthy\",\n  \"circuit_state\": \"closed\",\n  \"failure_count\": 0,\n  \"last_check\": \"2024-01-15T10:30:00Z\"\n}\n```\n\n**Verification:**\n- [ ] Circuit state is `closed`\n- [ ] Failure count is `0`\n- [ ] Status is `healthy`\n- [ ] No fallback flags in response\n\n**What's Happening:**\n- Circuit breaker is in CLOSED state\n- All requests pass through to actual service\n- Failures are being counted (currently 0)\n- System operating at full capacity\n\n---\n\n### Scenario 2: Configure Circuit Breaker\n\n**Objective:** Set up circuit breaker with specific thresholds\n\n**Steps:**\n\n1. Navigate to **Circuit Config** tab\n2. Select `userService` from dropdown\n3. Set configuration:\n   - Status: `healthy`\n   - Failure Threshold: `3` (lower for testing)\n   - Timeout: `5000`\n   - Reset Timeout: `15000` (lower for testing)\n4. Click **Apply Configuration**\n\n**Expected Response:**\n```json\n{\n  \"success\": true,\n  \"message\": \"Circuit breaker configured for userService\",\n  \"configuration\": {\n    \"service_name\": \"userService\",\n    \"failure_threshold\": 3,\n    \"timeout_ms\": 5000,\n    \"reset_timeout_ms\": 15000\n  }\n}\n```\n\n**Verification:**\n- [ ] Configuration applied successfully\n- [ ] Failure threshold set to 3\n- [ ] Reset timeout set to 15000ms\n\n**What's Happening:**\n- Circuit breaker will open after 3 consecutive failures\n- After 15 seconds without requests, will try recovery\n- Timeout for each request is 5 seconds\n\n---\n\n### Scenario 3: Trigger Circuit Open - Service Failure\n\n**Objective:** Simulate service failures and trigger circuit breaker opening\n\n**Steps:**\n\n1. Navigate to **Failure Management** tab\n2. Select `userService` from dropdown\n3. Set Error Code: `TIMEOUT`\n4. Set Error Message: `Connection timeout to database`\n5. Click **Record Failure** three times (3 = threshold)\n\n**Response After 1st Failure:**\n```json\n{\n  \"success\": true,\n  \"circuit\": {\n    \"service_name\": \"userService\",\n    \"failure_count\": 1,\n    \"failure_threshold\": 3,\n    \"circuit_state\": \"closed\"\n  }\n}\n```\n\n**Response After 3rd Failure:**\n```json\n{\n  \"success\": true,\n  \"circuit\": {\n    \"service_name\": \"userService\",\n    \"failure_count\": 3,\n    \"failure_threshold\": 3,\n    \"circuit_state\": \"open\"\n  }\n}\n```\n\n**Verification:**\n- [ ] Failure count increments with each click\n- [ ] Circuit state changes to `open` after 3rd failure\n- [ ] Response confirms state transition\n\n**What's Happening:**\n- Failures recorded incrementally\n- Failure count = 1, 2, 3\n- After 3rd failure, circuit OPENS\n- Circuit breaker is now protecting against cascading failures\n\n---\n\n### Scenario 4: Using Fallback Strategy - Circuit Open\n\n**Objective:** Confirm system uses fallback when circuit is open\n\n**Steps:**\n\n1. *Circuit should be OPEN from Scenario 3*\n2. Navigate to **Fallback Config** tab\n3. Select `userService`\n4. Set Fallback Type: `cache`\n5. Ensure \"Fallback Enabled\" is checked\n6. Click **Apply Fallback Configuration**\n\n**Response:**\n```json\n{\n  \"success\": true,\n  \"message\": \"Fallback strategy enabled for userService\",\n  \"fallback\": {\n    \"service_name\": \"userService\",\n    \"enabled\": true,\n    \"type\": \"cache\",\n    \"cached_data\": { \"id\": 1, \"name\": \"Alice (cached)\" }\n  }\n}\n```\n\n**Now Test Fallback:**\n\n7. Navigate to **Make Call** tab\n8. Select `userService`\n9. Click **Make Call (with Fallback)**\n\n**Expected Response:**\n```json\n{\n  \"success\": true,\n  \"data\": {\n    \"user\": { \"id\": 1, \"name\": \"Alice (cached)\" },\n    \"posts\": [],\n    \"analytics\": null\n  },\n  \"degraded\": true,\n  \"message\": \"Using fallback - userService is unavailable\"\n}\n```\n\n**Verification:**\n- [ ] Response has `degraded: true`\n- [ ] User data comes from cache (marked \"cached\")\n- [ ] Posts are empty array (default fallback)\n- [ ] Analytics are null (partial fallback)\n- [ ] Request succeeds despite circuit being open\n\n**What's Happening:**\n- Circuit is OPEN (protecting failing service)\n- Request intercepted before reaching service\n- Fallback strategy (cache) returns immediately\n- User still gets response, system is degraded but functional\n\n---\n\n### Scenario 5: Circuit Recovery - Half-Open Testing\n\n**Objective:** Trigger circuit recovery from open to closed state\n\n**Steps:**\n\n1. *Circuit should be OPEN from previous scenarios*\n2. Navigate to **Failure Management** tab\n3. Select `userService`\n4. Click **Reset Circuit** to move to HALF_OPEN\n\n**Response:**\n```json\n{\n  \"success\": true,\n  \"message\": \"Circuit reset to HALF_OPEN for userService\",\n  \"circuit\": {\n    \"service_name\": \"userService\",\n    \"state\": \"half_open\",\n    \"failure_count\": 0\n  }\n}\n```\n\n**Check Circuit State:**\n\n5. Navigate to **Health Check** tab\n6. Click **Get Service Health**\n\n**Response:**\n```json\n{\n  \"service_name\": \"userService\",\n  \"status\": \"healthy\",\n  \"circuit_state\": \"half_open\",\n  \"failure_count\": 0\n}\n```\n\n**Now Test Recovery:**\n\n7. Navigate to **Make Call** tab\n8. Click **Make Call (with Fallback)**\n\n**Response (Success = Close Circuit):**\n```json\n{\n  \"success\": true,\n  \"data\": {\n    \"user\": { \"id\": 1, \"name\": \"Alice\" },\n    \"posts\": [...],\n    \"analytics\": { \"views\": 1000 }\n  },\n  \"degraded\": false,\n  \"message\": \"Service recovered - circuit closed\"\n}\n```\n\n**Verification:**\n- [ ] Circuit state moved from OPEN → HALF_OPEN\n- [ ] Failure count reset to 0\n- [ ] Service call succeeds\n- [ ] Response has `degraded: false`\n- [ ] Full data available (no fallback used)\n- [ ] Next health check shows circuit is `closed`\n\n**What's Happening:**\n- Circuit in HALF_OPEN state, testing recovery\n- One successful request allowed through\n- If succeeds, circuit returns to CLOSED\n- System back to normal operation\n- If had failed, circuit would reopen (back to OPEN)\n\n---\n\n### Scenario 6: System Degradation - Multiple Service Failures\n\n**Objective:** Test graceful degradation with multiple services failing\n\n**Steps:**\n\n1. Click **Get System Health**\n\n**Response:**\n```json\n{\n  \"system_status\": \"degraded\",\n  \"overall_health\": 66.67,\n  \"services\": {\n    \"userService\": {\n      \"status\": \"down\",\n      \"circuit_state\": \"open\"\n    },\n    \"postService\": {\n      \"status\": \"healthy\",\n      \"circuit_state\": \"closed\"\n    },\n    \"analyticsService\": {\n      \"status\": \"down\",\n      \"circuit_state\": \"open\"\n    }\n  },\n  \"timestamp\": \"2024-01-15T10:30:00Z\"\n}\n```\n\n**Make API Call:**\n\n11. Navigate to **Make Call** tab\n12. Click **Make Call (with Fallback)**\n\n**Response:**\n```json\n{\n  \"success\": true,\n  \"data\": {\n    \"user\": { \"id\": 1, \"name\": \"Alice (cached)\" },\n    \"posts\": [{ \"id\": 1, `degraded`\n- [ ] Overall health is 66.67% (2 of 3 services healthy)\n- [ ] userService circuit is `open`\n- [ ] analyticsService circuit is `open`\n- [ ] postService circuit is `closed` (still 5000ms\n- Per request: 5000ms\n- 100 concurrent requests: All blocked for 5s\n```\n\n**With Circuit Breaker (Actual):**\n```\nCircuit OPEN (after 5 failures):\n- Fallback: 10ms (cache lookup)\n- Per show failure count incrementing\n```\n\n### Issue: Fallback Not Triggered\n**Check:**\n- Circuit state is OPEN\n- Fallback is enabled\n- Fallback type is configured\n\n**Fix:**\n```javascript\n// In 'half_open';\ncircuits[service].failureCount = 0;\n```\n\n---\n\n## Cleanup\n\nTo stop servers:\n\n```bash\n# Stop backend\n^C (Ctrl+C)\n\n# Stop React frontend\n^C (Ctrl+C)\n```\n\nTo reset all
