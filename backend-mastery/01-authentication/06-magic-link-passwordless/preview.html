Secure authentication without passwords

What is Magic Link?

Magic link authentication is a passwordless method where users receive a unique token via email. Clicking the link automatically logs them in without entering a password.

🔑 Traditional Login

  • User creates password
  • User remembers password
  • User types password
  • Server checks password hash

✉️ Magic Link

  • No password to create
  • Nothing to remember
  • Click link in email
  • Automatically logged in
Key Benefit: User proves identity by accessing their email account. No password needed.

How Magic Links Work

Step 1: User enters email address ↓ Step 2: Server generates random token (32 bytes) Example: "a3f2b1e9d7c4f8a2b5e1d9c3..." ↓ Step 3: Store token with expiration (15 minutes) ↓ Step 4: Send email with magic link https://app.example.com/auth/verify/TOKEN ↓ Step 5: User clicks link in email ↓ Step 6: Frontend extracts token from URL ↓ Step 7: Frontend sends token to backend ↓ Step 8: Server validates token: - Exists in database? - Not expired? - Not already used? ↓ Step 9: Mark token as used (one-time only) ↓ Step 10: Generate JWT access token ↓ Step 11: Return JWT to user ↓ Step 12: User logged in, can access app

Token Security

1. Token Length & Randomness

32 bytes (256 bits) generated with crypto.randomBytes()

const token = crypto.randomBytes(32).toString('hex') // Result: 64-character hex string // Unguessable: 2^256 = 1.1 × 10^77 combinations

2. Token Expiration

15-minute window balances security (no old tokens) with UX (user has time to click)

expiresAt = new Date(Date.now() + 15 * 60 * 1000) if (new Date() > expiresAt) → 401 Unauthorized

3. One-Time Use

Token can only be used once. Prevents replay attacks.

if (token.used) → 401 Unauthorized token.used = true // Mark immediately

4. HTTPS Transmission

Token must be transmitted over HTTPS to prevent interception

✓ GOOD: https://app.com/auth/verify/TOKEN ✗ BAD: http://app.com/auth/verify/TOKEN

Security Features

🔒 Token Randomness: 256-bit cryptographically random. Impossible to guess (1.1 × 10^77 possibilities).
⏱️ Time-Limited: 15-minute expiration. Old emails can't be used to hijack account.
🔐 One-Time Use: Token immediately marked used. Prevents replay attacks and account takeover.
📧 Email Verification: User proves identity by accessing email account. Strong identity proof.
⚠️ Note: Magic link ≠ 2FA. If email is compromised, account is at risk. Add 2FA for extra security.

Attack Prevention

Attack 1: Brute Force Tokens

Attacker tries to guess random token

Attacker tries: 1 million guesses per second Time to break: 3.6 × 10^63 years Result: ✓ IMPOSSIBLE

Attack 2: Token Reuse

Attacker intercepts token from email, tries to use it

First use: Token works, user logged in Second use: Token marked used=true → 401 Unauthorized Result: ✓ PREVENTED

Attack 3: Expiration Bypass

Attacker waits 20 minutes, then tries old token

Token created: 10:00:00 Token expires: 10:15:00 Attacker tries: 10:20:00 (5 minutes late) Result: ✓ REJECTED (expired)

Attack 4: Email Interception

Attacker gains access to user's email, clicks link

Required: Email account compromise Gain: Access to user's account Prevention: Add 2FA, email notifications, IP tracking

Security Best Practices

✓ Always HTTPS: Magic links must be transmitted over HTTPS. Tokens in URLs need encryption.
✓ 15-Minute Expiry: Balances security (no old tokens) with UX (user has time to click).
✓ One-Time Use: Token marked used immediately. Mark before responding to prevent race conditions.
✓ Rate Limiting: Max 10 send-magic-link per email per hour. Prevents spam and abuse.
✓ Token Cleanup: Delete expired tokens periodically. Reduces database size.
✓ Email Notifications: Notify user of login attempt. If unexpected, user can change password.
