🔐 WebAuthn & Passkeys

Passwordless authentication using biometrics

What is WebAuthn?

WebAuthn is a secure authentication standard that replaces passwords with cryptographic credentials. Users authenticate using biometrics (Face ID, fingerprint) or hardware security keys instead of typing passwords.

🔓 Traditional Login

  • User remembers password
  • Types password to login
  • Server checks password hash
  • Vulnerable to breaches

🔐 WebAuthn Passkey

  • No password to remember
  • Biometric (face/fingerprint)
  • Cryptographic proof of identity
  • Phishing-resistant
Key Insight: Server stores your PUBLIC key. Only your device (with PRIVATE key) can prove you own the account.

Registration Flow

Step 1: User clicks "Sign up with Passkey" ↓ Step 2: Server generates random CHALLENGE (32 bytes) ↓ Step 3: Server sends challenge to browser ↓ Step 4: Browser shows biometric prompt (Face ID / Fingerprint / Security Key) ↓ Step 5: User authenticates (successful scan) ↓ Step 6: Device generates KEY PAIR: • Private Key (secret, on device only) • Public Key (shared with server) ↓ Step 7: Device signs challenge with private key ↓ Step 8: Browser sends signed data + public key ↓ Step 9: Server verifies signature using public key ↓ Step 10: Server stores public key → User registered ✓

Authentication Flow

Step 1: User clicks "Sign in with Passkey" ↓ Step 2: Server generates NEW random CHALLENGE ↓ Step 3: Browser shows biometric prompt ↓ Step 4: User authenticates (face/fingerprint) ↓ Step 5: Device signs challenge with PRIVATE KEY ↓ Step 6: Browser sends signed challenge ↓ Step 7: Server verifies signature with stored PUBLIC KEY ↓ Step 8: ✓ User is authenticated (no password needed) ↓ Step 9: Server returns JWT tokens ↓ Step 10: User can access protected routes

Key Concepts

1. Challenge

A random 32-byte value generated by the server. Each registration/authentication gets a NEW challenge. Prevents attackers from replaying old signatures.

challenge = "F8Ys_xp7c3K5x9MlQ..." (base64url)

2. Public Key Cryptography

Two mathematically linked keys: Private key (secret) signs data, Public key (public) verifies signature. If signature is valid, you know the private key owner created it.

Private Key: Only on user's device Public Key: Stored on server Signature: Created by private key, verified by public key

3. Relying Party (RP)

Your server/application identified by domain. Credentials are bound to this origin - prevents phishing and cross-origin attacks.

RP_ID = "example.com" RP_ORIGIN = "https://example.com" (Credential only works for example.com)

4. Counter (Clone Detection)

Each time a key is used, counter increments. If counter doesn't increase, the key might be cloned. Backward counter = reject authentication.

First auth: counter = 0 Second auth: counter = 1 Third auth: counter = 2 (If counter = 1 again → REJECT "Possible cloning")

No Passwords

🛡️

Phishing-Resistant

Credential bound to domain. Works only on legitimate site.

✔️

Cryptographic Proof

Signature proves you have the private key. Mathematical certainty.

⏱️

Clone Detection

Counter prevents key cloning. Device tampering detected.

Attack Prevention Examples

Attack 1: Database Breach

❌ Traditional: Attacker steals password hashes → cracks them → accesses accounts
✓ WebAuthn: Attacker steals public keys → public keys useless without private key → can't login

Attack 2: Phishing

❌ Traditional: User visits fake.example.com, types password → attacker has password → accesses real account
✓ WebAuthn: User visits fake.example.com, device checks origin → credential only valid for example.com → login fails, phishing prevented

Attack 3: Replay Attack

❌ Traditional: Attacker captures login request → replays it → gains access
✓ WebAuthn: Each login uses different challenge → old signature invalid for new challenge → replay impossible

Testing the Module

Step 1: Start Registration

Frontend sends email + name to server

POST /auth/webauthn/register/start { "email": "user@example.com", "name": "John Doe" }

Step 2: Device Registration

Browser prompts for biometric, device generates key pair and signs challenge

Browser shows: "Scan your fingerprint to register..." Device action: Generate public/private key pair Device action: Sign challenge with private key

Step 3: Complete Registration

Frontend sends signed credential to backend

POST /auth/webauthn/register/complete { "userId": "uuid-from-step-1", "credential": { "id": "credential-id", "publicKey": "base64-encoded-public-key", "counter": 0 } }

Step 4: Start Authentication

User tries to login, server generates new challenge

POST /auth/webauthn/authenticate/start { "email": "user@example.com" }

Step 5: Device Authentication

Browser prompts for biometric again, device signs new challenge

Browser shows: "Scan your fingerprint to login..." Device action: Sign new challenge with private key Server action: Verify signature with stored public key

Step 6: Complete Authentication

User is authenticated with JWT tokens

POST /auth/webauthn/authenticate/complete 201 OK { "accessToken": "jwt...", "refreshToken": "jwt...", "user": {...} }

Quick Start Checklist

  1. Install dependencies:
    npm install
  2. Set environment variables:
    cp .env.example .env # Edit .env with: # RP_ID=localhost # RP_ORIGIN=http://localhost:3000 # JWT_SECRET=your-secret
  3. Start server:
    node server.js
  4. Start frontend:
    npm start (in separate terminal)
  5. Test Registration:
    Click "Register with Passkey" button
  6. Test Authentication:
    Click "Sign in with Passkey" button
  7. Verify Protected Route:
    GET /api/me (requires JWT token)

Security Best Practices

🔐 Always HTTPS: WebAuthn requires secure context. Force HTTPS in production.
🔐 Match RP_ID: Set RP_ID to your domain. Prevents cross-origin attacks.
🔐 Unique Challenges: Generate new challenge for each registration/auth. Prevents replay attacks.
🔐 Validate Counter: Check counter increments. Detects cloned keys.
🔐 Backup Codes: Generate recovery codes during registration. Users can recover if device lost.
🔐 Strong JWT Secret: Use 32+ character random secret. Store securely in environment.
